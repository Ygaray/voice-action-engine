## Analysis of the 12 core REMOVED lines (executor, from javap of the W10 jar)

Eleven are real binary breaks. v1.1.0 added one parameter with a default value to eight public constructors. Source callers still
compile, so Metalava's signature compatibility check passes. But the old JVM constructor, and its synthetic `$default` constructor
taking a DefaultConstructorMarker, no longer exist. Code compiled against v1.0.1 that calls them fails with NoSuchMethodError on
v1.1.0. The new constructors in the W10 jar:

| class | v1.0.1 ctor removed | W10 ctor adds |
|---|---|---|
| core.commit.ActionEvent | (String, String, ExecutedAction) | trailing String |
| core.commit.ExecutedAction | 2 synthetic $default ctors (int, String, boolean, String, String, Map, Object, boolean, [int,] DCM) | a String before the trailing boolean |
| core.commit.HeldProposal | (String, String, List, Object, String) | trailing String |
| core.pipeline.CommandOutcome$Completed | (RunEffects, String, TerminalCall, boolean) | trailing List<String> |
| core.pipeline.CommandOutcome$Unhandled | (RunEffects, EscalationReason) | trailing boolean |
| core.pipeline.TierPolicy | synthetic $default (boolean, String, Set, int, long, int, Long, DCM) | a long |
| core.telemetry.CommandTrace | full ctor (..., List<TierAttempt>, List<TraceCode>) + its $default | trailing StartTierSelection |
| core.telemetry.TierAttempt | 2 synthetic $default ctors (..., long, List, [int,] DCM) | a boolean after the long |

(DCM = kotlin.jvm.internal.DefaultConstructorMarker; package prefix io.github.ygaray.voiceactionengine omitted.)

One is not a consumer-facing break: `SingleShotStrategy.access$submitAll(...)` has flags `ACC_PUBLIC, ACC_STATIC, ACC_FINAL,
ACC_SYNTHETIC` in the v1.0.1 jar (`javap -p -v`). It is a compiler-generated accessor for a private member. No consumer source can
reference it, and the W10 jar has replaced it with other `access$...` accessors after the strategy refactor.

Per plan 20-08 Task 3 and must_have 5, a removed public member is a binary break that Metalava missed and blocks the tag. This
evidence file records the red result. The executor did NOT close window 20-02, did NOT append a rule H1 block to cut-handoff.txt and
did NOT route to a gap plan. Those decisions were handed to the milestone master per its dispatch instruction (report a red result,
act no further than recording). A fix (for example @JvmOverloads, or explicit secondary constructors keeping the v1.0.1
signatures) changes code. It is therefore a new commit and a new W, and plans 20-07 onward restart.
