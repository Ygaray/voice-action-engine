## Execution notes

- Two sequential Gradle invocations with the low-memory recipe (never in parallel, never `./gradlew --stop`). Capture
  each real exit status, never behind a pipe.
- Memory guard (hard stop, run immediately before EACH Gradle invocation, including any development re-run):
  `awk '/^MemAvailable:/{exit !($2>=5242880)}' /proc/meminfo && ! pgrep -f '[v]oice-action-engine/gradle/wrapper/gradle-wrapper.jar' >/dev/null`
  (MemAvailable at least 5 GiB; no other VAE Gradle build, whose wrapper jar path appears on its command line). Also
  record the read-only `free -h` and `pgrep -af '[G]radleDaemon'` output; another project's build in progress is a stop
  too, and an idle daemon is allowed only while the memory floor holds. On a failed guard: record the readings in the
  SUMMARY, start nothing, kill nothing, and report to the driver.
- No code, script, doc or test file may change in this plan. If a gate is red, record it and route it to a gap plan;
  the wiring SHA candidate is then whatever HEAD carries the fix.
