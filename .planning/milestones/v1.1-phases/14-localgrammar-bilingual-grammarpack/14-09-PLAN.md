<objective>
Consume the D-12 TESTER window: record what the platform speech recognizer actually emits for the 14-02 prompts
(digits vs words, accents, punctuation, decimal marks) and commit the filtered results as fixtures, or, when no window
is relayed before the phase closes, record the A12 deferral so the phase closes on the strict golden table.

Purpose: the strict number table rejects what it cannot verify; real recognizer output tells plan 14-10 which proven
forms to accept. Mechanism (planner decision, open item OI-8): a VAE-owned opt-in instrumentation tool synthesizes each
prompt with on-device TTS and feeds the audio to the platform recognizer through `RecognizerIntent.EXTRA_AUDIO_SOURCE`,
the same file-feed mechanism stt-engine proved on this exact device (precision 0.994). It does not reuse the stt demo
app, whose stimulus generator has fixed utterances and would need edits in another repository plus a second Gradle
build on a memory-tight host.
This plan is not autonomous: it needs the orchestrator's relayed TESTER window (Phases 12, 13 and 19 share one TESTER).
No API keys, no spend.
Output: the tool (androidTest-only), `14-WINDOW-GRANT.md` relayed then consumed (or deferred), `stt-fixtures.tsv`.
</objective>
