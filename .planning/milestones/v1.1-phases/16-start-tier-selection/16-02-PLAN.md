## Execution notes

- Phase branch, serial execution, host-safe Gradle recipe, one invocation at a time, never `--stop`. The repo gates
  listed in 16-01 "Execution notes" apply unchanged: no enum, data class, default-arg constructor, public static
  field, banned constant names, `@Suppress`, `runCatching`, model/vendor words or `SYSTEM_PROMPT`; ReturnCount 2,
  12 functions per class, MatchingDeclarationName.
- Kotlin rejects a public class whose supertype is internal. That is why the picking hook is an internal member of
  `TierSelector` (research correction 1, assumption A1) and not an internal intermediate class. If the first compile
  disagrees, keep the hook design anyway: it compiles either way.
- `guarded` (`internal/Guarded.kt`) is the only sanctioned catch. Never write `catch (e: Exception)` or `runCatching`.
  Caller cancellation propagates through it.

<assumption_delta_decision>
The detector fired (`chosen`: "custom"; `pluralization`: "fallback"). The start tier used to be derived (Linear's
first eligible tier, or Fixed's named tier). Now a picker can choose it.
- Primary noun: `TierSelector` ("which tier a command starts at"). It was already the general public abstraction.
  Custom and Router are new variants of it, not a second concept alongside it.
- Decision: `no-change` for the public noun. At the internal hook it is `add-alongside`, accepted per D-01 (locked):
  the sync `startIndex` stays for Linear and Fixed so their path is the v1.0.1 code, and the suspend `picking` hook
  serves Custom and Router. Accepted debt: two internal start hooks. What would force a promote: a third selector
  that needs suspend behavior without the zero-call pre-pass, or a change to the Linear path. Either would make
  `PickingSpec` the only hook, with Linear and Fixed as degenerate picks.
- `fallback` (`router_fallback`) is a trace code, not a second source of truth: no-change.
- Invariant test: `TierWalkLinearCharacterizationTest` (16-01) plus its `linearAndFixedStartOnlyAtAnEligibleTier`
  case. Task 2 adds `selection == null` to every case.
</assumption_delta_decision>
