<objective>
Pin the orchestrator's redact-by-default ruling for the engine's action event string form: add the sentinel test and state
the policy in KDoc. Research found that the current string forms already print only ids, kind, flags and counts, so the
work is a policy statement plus a test with teeth, not a behaviour change.

Purpose: RT-01 asks that no argument value, utterance text, model output or key can reach a log through
`ActionEvent.toString()`. The existing output is already safe, but nothing pins it: a future edit that interpolates the
outcome token would leak silently. The sentinel test turns the policy into a regression gate. This plan is `:core` only and
lands before the later publication and negative-control plans, so the security audit that follows sees the finished tests.
Output: one sentinel test group in `ActionEventTest` and the KDoc policy in `CommitSink.kt`.

Plan decision made here (planner, `ai-auto`, recorded for review):
- PD-05: keep the printed shape (held run id shown only as set or null, which `HeldRunIdTest` already pins) and do not
  invent a placeholder format for redacted values: the ruling's "redacted" rendering applies to argument values, and no
  field of `ActionEvent` or `ExecutedAction` is one (they hold the app's outcome token, target ids, a provider call id and
  the app's context object, none of which is printed today). Printing the held run id's value instead would force an edit to
  `HeldRunIdTest` and contradicts the point that the run-id seam is app code.
- This plan depends on plan 03 only to keep one Gradle-running plan per wave on a memory-tight host; there is no code
  dependency.
</objective>
