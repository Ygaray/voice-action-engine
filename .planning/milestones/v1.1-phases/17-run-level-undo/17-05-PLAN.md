Build the standalone `:undo` journal's core path: the public seams (EntityAdapter, Compensator, UndoTicket), the
journal facade, the closed result set, and whole-scope verify-then-restore with loud refusals.

Purpose: UNDO-01..03 are the heart of A18. A non-voice app must be able to journal and undo with `:undo` alone. Undo
must restore every touched entity safely and refuse rather than clobber a later change (D-07). The result set is a
one-way door frozen at the tag (D-08). Capture happens inside apply (D-03), and the footprint is app-declared (D-04).
Output: the public surface of `:undo` (all but the group view, store and limits, which 17-07 adds), the internal
journal state and verifier, and seven test classes.

## Execution notes

- Depends on 17-02 only for host-memory serialization (one Gradle plan per wave). `:undo` never imports `:core`.
- Kotlin stdlib only. Use `synchronized` and `kotlin.coroutines.cancellation.CancellationException`. Never call an
  adapter or compensator while holding a lock.
- detekt runs with the defaults (buildUponDefaultConfig) on main and test: ReturnCount 2, LongMethod 60,
  CyclomaticComplexMethod 15, NestedBlockDepth 4, TooManyFunctions 12 per class, LongParameterList 6 per function and 9
  per constructor. Keep classes small and split internals into the files listed. Name every limit as a constant.
- One `@file:Suppress("TooGenericExceptionCaught")` per module (research assumption A6, Claude's discretion): `:undo`
  cannot import `:core`'s helper, so it gets its own `internal/Guard.kt`. The comment in `:core`'s Guarded.kt that calls
  its suppression "the repository's only one" is corrected to "this module's only one". This is preferred over a
  path-scoped detekt tune, because the rule stays active everywhere else.
- Non-generic EntityAdapter with `Any?` snapshots (research A3): a generic adapter would need an unchecked cast plus a
  second suppression inside `:undo`. The app casts in its own adapter.
- An applied-with-error action whose capture was never settled refuses as UNVERIFIABLE unless the live state still
  equals the before state (research A8: prefer a false refusal over a false restore). `nothingWritten()` is the app's
  escape hatch.
- No planning ids in source comments or KDoc. No app-domain words; use "item".
- There is no SPEC.md for this phase, so no SPEC edge or prohibition sections exist. Edge cases come from two
  places: the research (edit-since, deleted-since, recreated-since, chain broken, partial, cancellation mid-undo,
  concurrent second call, eviction) and the deterministic edge probe over UNDO-01..04 (idempotency, concurrency,
  adjacency, empty, ordering). Each one is pinned by a behavior bullet in 17-05..17-08.
