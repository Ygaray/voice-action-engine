  `:core:metalavaCheckCompatibility`.
- compositeSink fault policy (research Open Question 1, Claude's discretion, both readings satisfy the SB condition):
  **all children run, then one fixed-text exception (counts only) if any failed.** Choice and reason:
  - It keeps `sink_error` visible in the trace for a failing journal. Swallowing would hide it.
  - It never forwards a child's own exception or message, because app messages can carry user data.
  - The guarded helper reduces a fault to its class name anyway, so no original exception is available to rethrow
    without a second catch, which this repository forbids.
