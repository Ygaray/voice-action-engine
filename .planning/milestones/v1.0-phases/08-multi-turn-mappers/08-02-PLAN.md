<objective>
Encode tool results the way each dialect needs them, in the calls' emission order (XCR-03, D-04, D-05).

Anthropic already batches a turn's results into one user message with `is_error`. It now also orders them by call emission and omits an empty `content`.

Chat already sends one `role:tool` message per id. It now orders them, and it now marks an error at all: today the `is_error` flag is dropped on Chat, so the model cannot tell a failed tool from a successful one. The fix wraps an error result as `{"error": …}` and passes every other result through unchanged.

One test is reversed on purpose: `ChatMessageEncoderTest.eachToolResultIsItsOwnToolMessageInOrderAndErrorsAreSentUnchanged`.

Purpose: Phase 9's loop dispatches sequentially, and an app may return results in any order; the wire must still match the model's call order. A Chat model has to see that a tool failed.
Output: one helper added to the 08-01 file, two encoder edits, three extended test classes.

Contention: wave 2 is this plan only. It starts after 08-01 has merged and never runs two Gradle invocations at once.
</objective>

## Plan-level decisions (Review Dispositions)

- **Research A3, empty `role:tool` content:** send `""` unchanged. Encoding it as a space or a placeholder would change what the model sees, which is a product decision this phase has no basis for. Nothing documents a rejection. The risk is recorded in COVERAGE.md and in this plan's SUMMARY. If a captured Chat conversation ever answers 400 on empty tool content, it comes back as a gap. This is not a contract conflict.
