<objective>
Make "no arguments" decode as an empty object in every form providers and routers send it in (D-06), and make the Chat replay repair, and only repair, an echo that would otherwise be invalid input (D-01 refreshed; research A4).

Today a blank string, the text `null`, a JSON `null` and an absent `arguments` all fail as `MalformedToolArgs` on Chat, and an absent or null Anthropic `input` does too. Each of those fails a zero-argument tool call that is otherwise valid.

Two tests are narrowed on purpose because Phase 8 supersedes the behaviour they pinned: `ChatDecoderTest.badArgumentsAreMalformedToolArgs` and `AnthropicDecoderTest.aToolInputThatIsNotAnObjectIsMalformedToolArgs`. Their genuinely malformed inputs stay malformed.

Purpose: a loop that fails a valid zero-argument call is broken, and a replayed `"arguments": ""` risks an opaque provider 400 on the next turn.
Output: two decoder edits, one encoder edit, three extended test classes.

Contention: wave 3 is this plan only. It starts after 08-02 has merged and never runs two Gradle invocations at once.
</objective>

## Plan-level decisions (Review Dispositions)

- **Research A4, repairing a replayed Chat turn:** only a missing `role` and an empty-arguments form are repaired. The repair never fires on a valid replay, so the verbatim projection that D-01 locks stays byte-identical in the normal case. Ids are never touched (D-06). The Anthropic raw array is never repaired: real Anthropic answers always carry an `input` object, and thinking binding requires the array unmodified.
