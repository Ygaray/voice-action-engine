## Design note (why the body is read inside the callback)

Research suggested resuming with the Response and closing it in the `resume(value, onCancellation)` handler. This plan reads the body inside `onResponse` and resumes with plain data instead: a cancellation that arrives while the body is still streaming then reaches `Call.cancel()` (registered with `invokeOnCancellation`) and aborts the read, whereas a body read after resumption on the caller's dispatcher could only be stopped by the read timeout. It also needs no experimental coroutine API (research A1 disappears) and keeps the Response from ever leaving one function, which is D-02's "never escapes" in its strongest form. OkHttp's Callback contract allows reading the body in `onResponse`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app OkHttpClient -> library | the app may hand in a client carrying hooks the library must not inherit |
| library -> network | the key leaves in one request header |
| server -> library | status, headers and body strings are untrusted |
