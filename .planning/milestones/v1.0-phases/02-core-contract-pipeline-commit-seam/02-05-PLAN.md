<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| engine -> app gate | the gate decides whether a write may happen; it may throw or hang |
| engine -> app apply | the app's own write; may throw, report an error, or be cancelled mid-write |
| engine -> app sink (undo journal) | the journal must hear every real write exactly once |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-20 | Elevation of privilege | fail-open write when the gate throws or times out | high | mitigate | GateStep maps any non-cancellation throw to Hold with gate_error; nothing applies; test asserts applyCount 0 |
| T-02-21 | Repudiation | a write lost from the undo journal when cancelled mid-apply | high | mitigate | Specific CancellationException catch records is_error applied=true and delivers under NonCancellable before rethrowing |
| T-02-22 | Tampering | duplicate write after a sink failure | high | mitigate | Sink faults recorded as sink_error; no retry, no re-apply; applyCount asserted |
| T-02-23 | Spoofing | an is_error or held action presented to the user as success | high | mitigate | Kind rules in the behavior table; commits excludes is_error and held; held content is the fixed not-applied JSON |
| T-02-24 | Tampering | a batch's failing item aborting or corrupting siblings | medium | mitigate | Sequential per-item isolation; BatchIsolationTest proves siblings apply exactly once |
</threat_model>
