<objective>
Make every read answer with a typed, specific state and nothing else (KEY-03): the restored-backup case reports KeyMissing without ever creating a key, every failure maps through one explicit catch chain to a stable cause code (D-07), cancellation is never swallowed, reads never write (D-07), strict decoding turns corruption into a state (D-05 decode side), and `observe` gives the Settings UI the same states as a stream. The cause-code vocabulary is defined in exactly one file and recorded for the orchestrator.

Purpose: the user must see "re-enter your key" for a lost or corrupt key and "not configured" only for a key never stored; an opaque crash or a silently regenerated key would strand them.
Output: `SecretReader.kt` and `KeystoreCauses.kt` (new), read/observe/readSecret in `ApiKeyStore.kt`, four test classes, two DataStore fakes.

Contention: the phase runs strictly sequentially, one plan per wave (wave 3 is this plan only; it starts after 06-02 has merged), so no two plans ever run `:keystore` Gradle tasks at the same time; this plan never runs two Gradle invocations at once and uses task-scoped `:keystore` commands until its final `:keystore:check`.
</objective>
