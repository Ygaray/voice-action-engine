<objective>
Prove the whole storage path end to end on the JVM before anything is widened: one key saved for one provider goes through the shared AES/GCM code (D-08), lands as a Base64 ct/iv pair in a real temp-file DataStore that the caller injected (D-02, D-05 encode side), and reads back as `KeyState.Ready(last4)`. Then finish the build wiring every later plan needs: datastore-preferences in the published API with a check that keeps it there, a structural gate that the library never creates a DataStore (KEY-02), the androidTest toolchain and lint coverage, and the negative controls for both new gates.

Purpose: SC1's core path and KEY-02's "never opens a second DataStore" become mechanically enforced from wave 1, so every later plan builds on a proven slice and a guarded build.
Output: five new `:keystore` main files (the marker file is removed), a test support file and the tracer test, build wiring in three Gradle files, two new negative controls.

Contention: the phase runs strictly sequentially, one plan per wave (wave 1 is this plan only), so no two plans ever run `:keystore` Gradle tasks at the same time; this plan never runs two Gradle invocations at once and uses task-scoped `:keystore` commands until its final `:keystore:check :core:check`.
</objective>
