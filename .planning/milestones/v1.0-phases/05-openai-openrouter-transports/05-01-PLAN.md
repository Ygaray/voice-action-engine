<objective>
Give the Chat Completions dialect its strict-mode decision before any wire code exists: extend the shared optional-property detector so OpenAI's wider schema subset (anyOf, $defs) cannot hide an optional (research Finding 1, Pitfall 1), add the Chat eligibility rules with the engine-wins authority (D-06), and the data-driven strip that only touches the strict wire copy (D-07). PROV-12's core rule lives here; the encoder (05-04) and the contract test (05-10) consume it.

Purpose: strict mode makes every property required, so a missed optional is silent data loss in the consumer (SB reads "" and [] as "clear"). The detector is the one place that decides.
Output: one extended shared file, two new internal chat files, two test classes.

Contention: the phase runs strictly sequentially, one plan per wave (wave 1 is this plan only; it starts after no earlier plan has merged), so no two plans ever run `:providers` Gradle tasks at the same time; this plan never runs two Gradle invocations at once, uses task-scoped `:providers` commands until its final `:providers:check`.
</objective>

| T-05-04 | Denial of service | a huge or deeply nested schema exhausting the walk | low | accept | schemas are app-authored constants; size limits short-circuit eligibility; recursion depth bounded by schema depth the app wrote |
</threat_model>
