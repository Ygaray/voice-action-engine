<objective>
Pin the response side of the wire with golden bodies (success criterion 2): every documented OpenAI and OpenRouter answer shape becomes a manifest row replayed through the production decoder and error map, with derivatives documented now (D-13) and real sanitized captures appended later by the key-gated plan 05-12 (D-12, D-14). The same test enforces golden hygiene so a captured body can never be committed unsanitized.

Purpose: "typed outcomes rather than crashes or fabricated parses" must hold on recorded bodies, not only hand-built fixtures; the manifest is the one place that says which goldens are real.
Output: one derivative file, one manifest, one replay test class (test sources only).

Contention: the phase runs strictly sequentially, one plan per wave (wave 7 is this plan only; it starts after 05-06 has merged), so no two plans ever run `:providers` Gradle tasks at the same time; this plan never runs two Gradle invocations at once, uses task-scoped `:providers` commands until its final `:providers:check`.
</objective>

Conventions fixed here (05-12 relies on them):
- `derived.json` is one JSON object: key = case name, value = the response body object.
- `MANIFEST.tsv`: lines starting with `#` are comments; first non-comment line is the header `case	vendor	provenance	source	http_status	tool_choice	expected	absent_keys	note`; `source` is `derived.json#<case>` for derived rows and `captured/<vendor>-<label>.json` for captured rows (directory `golden/chat/responses/captured/`, created by 05-12); `tool_choice` is required, auto or `-` (non-2xx); `expected` is `success:<StopReason value>:<comma-separated tool names or ->` or `failure:<FailureReason code>`; `absent_keys` is a comma-separated list of dotted paths into the first tool call's arguments (array index as a number) or `-`.
Test helpers in ChatGoldenReplayTest.kt: private manifest parser, row loader and outcome formatter; one top-level `internal fun goldenHygieneViolations(text: String): List<String>` (returns one message per violated rule, empty when clean) that 05-11's sanitizer test reuses.
No main-source or public API change.
