<objective>
Wire the Chat Completions dialect end to end: the public `ChatCompletionsProvider` with its two factories (D-01), the transport that vets the key, POSTs the golden-shaped body, decodes or maps the error and retries once only when it can help (PROV-09/11/13 for Chat, success criterion 4), and the public attempt observer that carries the finish-reason note (D-09). The first test of every later plan runs through this provider.

Purpose: a consumer can now register `ChatCompletionsProvider.openAi { }` or `.openRouter { }` on a pipeline and point the same commands at either vendor (phase goal).
Output: three chat main files (two public types plus the transport), one transport test class, one API-shape test update.

Contention: the phase runs strictly sequentially, one plan per wave (wave 6 is this plan only; it starts after 05-05 has merged), so no two plans ever run `:providers` Gradle tasks at the same time; this plan never runs two Gradle invocations at once, uses task-scoped `:providers` commands until its final `:providers:check`.
</objective>
