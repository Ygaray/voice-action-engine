<objective>
Discharge the v1.0.0-blocking limits obligation for SingleShot and prove the cached prefix is never touched. SingleShot does not loop, but the orchestrator's limits precondition (Runtime Decision, carried from Phase 11) still requires the 6 / 60000 / 4096 limits to be enforced from `session.policy` / `session.tokensUsed` and covered by named tests: per-turn max tokens is passed through, the token ceiling is checked before the call (after an expensive earlier tier) and after it (before any resolve or write, SB's order), and exactly one provider call happens under every policy, including `maxIterations = 2`. Then prove D-03's cache rule: per-command text reaches only the user message.

Purpose: Phase 11 checks for these tests by name before the tag; the cache test protects the Anthropic breakpoint and OpenAI automatic caching that every SingleShot call depends on.
Output: one main file changed, two new tests.

Contention: the phase runs strictly sequentially, one plan per wave (wave 5 is this plan only); this plan never runs two Gradle invocations at once.

Boundary note: pre-call uses `>=` (a call costs at least one token, so at the ceiling nothing more may be spent) and post-call uses `>` (mirrors SB). If `evidence/seam-signoff.txt` carries a `CARRY:` line for item 6, use that boundary instead and adjust the boundary tests to it.
