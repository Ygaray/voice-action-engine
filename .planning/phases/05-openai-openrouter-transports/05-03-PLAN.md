<objective>
Map every OpenAI and OpenRouter error answer to the engine's typed failures before any transport exists: the non-2xx body and the HTTP-200 body that carries an `error` object go through one status-first table with in-memory refinements (D-11, D-04 reactive), keeping only status, error type and request id (TEL-04). Also move the key-header safety check into the shared `http/` helpers so the Bearer key is vetted exactly like Anthropic's (research Pattern 6, Pitfall 9).

Purpose: OpenRouter reports rate limits and upstream failures inside 200 answers, OpenAI reports exhausted credit as a 429; without this map those become retried "successes" or pointless retries.
Output: one internal chat file, one shared helper moved, two test classes touched.

Contention: the phase runs strictly sequentially, one plan per wave (wave 3 is this plan only; it starts after 05-02 has merged), so no two plans ever run `:providers` Gradle tasks at the same time; this plan never runs two Gradle invocations at once, uses task-scoped `:providers` commands until its final `:providers:check`, and is the only plan in the phase that edits `http/SafeFields.kt` and `anthropic/AnthropicTransport.kt`.
</objective>

| T-05-09 | Tampering | hostile error type or request id making FailureDetails throw and hide the real failure | medium | mitigate | safeToken / safeRequestId drop it to null; hostile-value tests (Task 2) |
