<objective>
Encode a neutral `ProviderRequest` as the exact Chat Completions body each vendor needs, and pin it with committed golden request bodies (success criterion 1): nested tool shape, strict only where safe with the strict-only strip (D-06, D-07, PROV-12), the reasoning and token parameters per model family (D-03), named or reshaped tool choice and OpenRouter's `require_parameters` on forced calls (D-01).

Purpose: CalTracker's flat tool shape was rejected in production; golden bodies make every wire field reviewable and catch drift.
Output: two internal chat files, a shared test fixture file, two test classes, two golden JSON files.

Contention: the phase runs strictly sequentially, one plan per wave (wave 4 is this plan only; it starts after 05-03 has merged), so no two plans ever run `:providers` Gradle tasks at the same time; this plan never runs two Gradle invocations at once, uses task-scoped `:providers` commands until its final `:providers:check`.
</objective>
