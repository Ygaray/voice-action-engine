- A3 (OpenRouter accepts the OpenAI-shaped body): held. R1, R2, R3 and R6 were 200 with tool_calls answers, including routing to anthropic/claude-haiku-4.5 (served by Amazon Bedrock).
- A4 (parallel_tool_calls with require_parameters, R5): NOT accepted. HTTP 404 with the routing text "No endpoints found that can handle the requested parameters", failed_routing_step "Filter by Parameters" (routing_funnel went from 5 endpoints to 2, then none). The OpenRouter vendor must keep parallel_tool_calls off. Typed outcome from the shipped decoder was failure:model_not_found, not model_unsupported (see gap 1).
- A5 (cache_write counted in prompt_tokens): not observed. R6 (Haiku via OpenRouter) reported cache_write_tokens 0 and cached_tokens 0, so there was no write to compare. Still open for Phase 10's smoke or a Haiku call that sets an explicit cache breakpoint.

- numeric bounds in strict mode: not exercised by this plan. The encoder strips minimum, maximum and exclusiveMinimum before sending strict (stripForChatStrict), so the strict C1 call (200) proved the stripped schema is accepted; raw bounds were never sent.
