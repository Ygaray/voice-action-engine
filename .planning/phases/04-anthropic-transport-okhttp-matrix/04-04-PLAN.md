<objective>
Make every way an Anthropic call can fail come back typed and loud: the status-first error table (D-08, orchestrator decision 3), I/O and timeout mapping (D-04, PROV-13), and cancellation that reaches the HTTP call (PROV-04 SC4), with error bodies parsed and discarded so failures carry only status, error type and request id (TEL-04 failure half).

Purpose: "every failure surfaced as a specific, loud reason, never a silent or opaque one" (PROJECT core value) for the transport layer.
Output: `AnthropicErrors.kt`, the transport's failure branches, three test classes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> library | error status, headers and bodies are untrusted and may echo the prompt or key |
| caller -> library | the caller may cancel at any time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-15 | Information disclosure | provider error body echoing the prompt, transcript or key into a failure | high | mitigate | parse-and-discard; AnthropicErrorInfo holds booleans and safe tokens only; canary-marker assertions in every table case (Tasks 1-2) |
| T-04-16 | Information disclosure | exception messages (which can include URLs or socket details) in failures | medium | mitigate | Timeout() and Network() carry no text; exception messages are never read; toString assertions (Task 3) |
| T-04-08 | Denial of service | hostile error.type or request id breaking FailureDetails | medium | mitigate | safeToken / safeRequestId with null fallback; hostile-string cases (Task 2) |
| T-04-17 | Denial of service | cancelled command leaving an HTTP call running | medium | mitigate | Call.cancel on cancellation, ensureActive before mapping; dispatcher-drained assertions (Task 3) |
| T-04-18 | Repudiation | spend limit misreported as a transient rate limit and retried silently | low | mitigate | spend-cap 429 and user spend-limit 400 map to Billing (Task 2); 04-05 never retries them |
</threat_model>
