## Fallback contract (inserted at Resolution step 3 of 03-06)

When the selection's provider is ON_DEVICE and it is not usable (the shared probe is false or faulted, or no ON_DEVICE provider is registered):
1. No fallback declared: record `on_device_unavailable`, refuse `ProviderUnavailable(ON_DEVICE, "on_device_unavailable")` (unchanged from 03-06).
2. Fallback declared and the gate function refuses its provider (tier declaration, allowedProviders, offlineOnly): record `on_device_unavailable` and `fallback_refused`, refuse with the same on-device failure; no credential lookup.
3. Fallback declared and permitted: record `provider_fallback`, then continue Resolution steps 4-6 with the fallback's provider and model (credential asked for the fallback provider only), and bind with `fallbackFrom = ProviderId.ON_DEVICE`. If a later step refuses (unregistered, missing key, capability lookup), that step's own reason for the fallback provider is the refusal (it is the actionable one) and its code is recorded after `provider_fallback`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device runtime -> engine | on-device availability is app or runtime code read twice per command |
| policy -> fallback | the declared fallback must obey the same policy as any selection |
| credential source -> fallback provider | a second provider's key is fetched only on the fallback path |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-29 | Information disclosure | an offlineOnly user's transcript sent to a cloud fallback | high | mitigate | Fallback re-checked by the same gate function (offlineOnly, allowedProviders, tier declaration); pre-check skips cloud-declaring tiers offline; tests for both layers |
| T-03-30 | Information disclosure | the fallback path fetching or sending the wrong provider's key | high | mitigate | Fallback credential lookup keyed by the fallback provider only; KeyIsolationTest fallback case |

| T-03-32 | Tampering | a second on-device probe API diverging from the pre-check's | medium | mitigate | One public gate feeding the one internal hook; counting-gate test |
| T-03-33 | Denial of service | a throwing or flapping gate crashing the run | low | mitigate | guarded probe at the router (on_device_probe_error, counts as unavailable); independent reads tested |
