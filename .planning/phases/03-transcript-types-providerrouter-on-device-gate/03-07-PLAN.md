<objective>
Wire the 03-06 router into the pipeline (PROV-02, PROV-03, CLN-04): `CommandSession.model()` returns the tier's `BoundModel`, resolved once per command per tier, lazily, and frozen (D-03); `commandPipeline { }` gains `provider(...)`, `providerSelection`, `credentials` and `capabilities(...)` with build-time validation; the pipeline exposes its `capabilityTable`; and the router reads the very same on-device probe instance the Phase 2 pre-check reads (Runtime Decision ondevice: one gate).

Purpose: this is where "selection once per command", "switch takes effect next command" and "a mid-command change does not apply" become structural, and where the app's seams become the only way provider, model and key reach the engine.

Output: 5 modified main files, 1 new test class.
</objective>
