<objective>
Create the three app seams through which provider, model, key and on-device availability enter the engine (PROV-02, PROV-10 types, CLN-04): `ProviderSelectionSource` / `ProviderSelection` / `SelectionRequest`, `CredentialSource` with its typed `CredentialLookup` result (D-02), and `OnDeviceCapability` with the ML-Kit-shaped `OnDeviceAvailability` (D-06). Add the one new failure leaf `CredentialUnreadable`, and the scripted test fakes the router and on-device tests (03-06, 03-07, 03-08) will use.

Purpose: the router (03-06, 03-07) and the on-device gate (03-08) are only as safe as these types: a typed credential result keeps "lost key" distinct from "not configured", a required model keeps model ids app-owned, and a fallback that can only hang off an on-device selection makes "no substitution" structural.

Output: 3 main files and one modified, 1 testFixtures file, 1 new and 1 extended test class.
</objective>

## Type contract

- `ProviderSelectionSource`: `public fun interface` with exactly one abstract `suspend fun select(request: SelectionRequest): ProviderSelection?`. KDoc: asked once per command per tier, lazily, on the tier's first model use; null means not configured; the library never reads settings itself.
- `SelectionRequest`: `public class SelectionRequest internal constructor(public val strategy: StrategyId)`; `toString` = `SelectionRequest(strategy=<id>)`. Later facts are new properties.
- `ProviderSelection(provider: ProviderId, model: String, fallback: ProviderSelection?)` plus secondary `ProviderSelection(provider: ProviderId, model: String)`. `init`: model non-blank; fallback rules per must_haves. Equality and hashCode by the three fields. `toString` = `ProviderSelection(provider=<p>, model=<m>, fallback=<p>/<m> or none)`. KDoc: the fallback is used only when the on-device gate does not report Available, and it is itself subject to the command's policy (offlineOnly, allowedProviders) and to the tier's declared providers; a tier that wants on-device-then-cloud declares both providers.
- `CredentialSource`: `public fun interface` with exactly one abstract `suspend fun credential(provider: ProviderId): CredentialLookup`. KDoc: the engine asks only for the provider it is about to call and refuses a credential stamped for another provider.
- `CredentialLookup`: `public abstract class CredentialLookup internal constructor()` with public final leaves `Present(credential: Credential)` (`toString` = `CredentialLookup.Present(provider=<p>)`), `Missing()` (equality by class), `Unreadable(cause: String)` (`require(isStableCode(cause))`, equality by cause, `toString` prints the cause). KDoc: open set (Phase 6's Keystore adapter maps onto it); Unreadable means the key exists but cannot be read, so the user should re-enter it.
- `OnDeviceCapability`: `public fun interface` with exactly one abstract `suspend fun availability(): OnDeviceAvailability`. KDoc: v1.0 ships no on-device implementation and the pipeline default reports `Unavailable("not_implemented")`; the same gate is consulted by the policy pre-check and by the router.
- `OnDeviceAvailability`: `public abstract class OnDeviceAvailability internal constructor()` with public final leaves `Available()`, `Downloadable()`, `Downloading()`, `Unavailable(code: String)` (`require(isStableCode(code))`); equality by class (and code); `toString` = `OnDeviceAvailability.<Leaf>` / `OnDeviceAvailability.Unavailable(code=<c>)`. KDoc: mirrors ML Kit statuses; only Available is usable in v1.0; open set.
- `FailureReason.CredentialUnreadable(provider: ProviderId, cause: String)`: code `credential_unreadable`, `require(isStableCode(cause))`, equality/hash/toString exactly like `ProviderUnavailable` (`describe`, `mixHash`). KDoc: the key exists but cannot be read; tell the user to re-enter it (distinct from NotConfigured).
