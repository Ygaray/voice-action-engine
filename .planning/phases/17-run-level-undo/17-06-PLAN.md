<objective>
Make every failure after verification exact and retryable: partial restores, compensators, cancellation and concurrent
calls.

Purpose: UNDO-03 says an undo "either completes or reports exactly what it couldn't restore, never a silent partial".
D-08 orders DB restores first, then idempotent compensators. A double tap or a cancelled undo must never write twice
or leave a stuck group.
Output: Restorer (per footprint component), Compensating (ordered, done marks), the IN_PROGRESS flag, and four test
classes.
</objective>

## Execution notes

- Kotlin stdlib only. Tests use `runSuspending`. For a suspended adapter, use a `suspendCoroutine` whose continuation
  the test stores and resumes later. Launch an undo without waiting via `startCoroutine` with a completion that
  records the result. Never add kotlinx-coroutines-test.
- Every adapter and compensator call goes through `guardedCall` from internal/Guard.kt. Cancellation is always
  rethrown.
- Per-entry state that must survive a failed or cancelled pass: restored keys, compensations done, and the undone
  flag. Mutate it only under the journal lock, after the call that justified it returned.
- No planning ids in source comments or KDoc.

## Artifacts this phase produces

This plan contributes (all internal, no new public API):
- `internal/Footprints.kt`: union-find over `EntityKey` (captured, created and touched keys) giving components.
- `internal/Restorer.kt`: restores components in reverse sequence. On a failure it stops that component and continues
  the others. It produces exact `Partial` lists.
- `internal/Compensating.kt`: runs registered compensators after DB restores, in reverse entry sequence, with per-entry
  done marks.
- In-progress compare-and-set on the group (`Refused` + `IN_PROGRESS`), released in `finally`.
- Tests `PartialRestoreTest`, `CompensatorTest`, `CancelMidUndoTest`, `IdempotentUndoTest`; `TestAdapter` fault
  injection (throw, race, suspend per id) and a `RecordingCompensator`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app adapter / compensator -> journal | App code may throw, race, suspend or be cancelled mid-undo |
| UI -> journal | A user can tap "Undo all" twice |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-19 | Tampering | double or concurrent undo | high | mitigate | Per-group compare-and-set in-progress flag; the second call is Refused(IN_PROGRESS) with nothing written; released in finally (IdempotentUndoTest) |
| T-17-20 | Repudiation | silent partial undo | high | mitigate | Exact Partial lists (RESTORE_FAILED, CHANGED_SINCE race, SKIPPED_AFTER_FAILURE, COMPENSATOR_FAILED); retry finishes only the remainder (PartialRestoreTest, CompensatorTest) |
| T-17-21 | Tampering | compensator re-run or run on stale data | medium | mitigate | Compensators run only after their entry's restores succeeded, with done marks; never on a refusal (CompensatorTest) |
| T-17-17 | Denial of service | cancellation leaving a stuck group | medium | mitigate | Cancellation is rethrown; the in-progress flag is released in finally; marks are written only after the call returned (CancelMidUndoTest) |
| T-17-15 | Information disclosure | exception messages in results | medium | mitigate | NotRestored carries errorClassOf only; a canary message is asserted absent (PartialRestoreTest) |
