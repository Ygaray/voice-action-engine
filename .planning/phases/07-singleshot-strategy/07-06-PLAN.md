<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model output -> app resolver -> gate | untrusted extraction becomes proposed writes that the app's gate admits or holds |
| app UI -> commitHeld | the user's later confirm or amendment re-enters the engine |
| engine -> printing/telemetry | every returned or delivered object can reach app logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-25 | Tampering | a weak or batch proposal written without the user's confirm | high | mitigate | S2/S3 assert held proposals apply nothing until commitHeld (Task 2) |
| T-07-26 | Tampering | one bad row aborting or corrupting the batch | medium | mitigate | S5 asserts per-item isolation with error and throw variants (Task 2) |
| T-07-27 | Repudiation | a deferred commit with no link to the original command | medium | mitigate | S2 asserts parentRunId, own close and idempotent repeat (Task 2) |
| T-07-28 | Tampering | a held tier escalating and a later tier writing again (duplicate write) | high | mitigate | aHeldProposalNeverReachesTheNextTier (Task 3) |
| T-07-29 | Information disclosure | transcript, arguments, system text or app context leaking from a SingleShot run | high | mitigate | noCanaryLeaksFromASingleShotRun sweeps outcome, events, sink, proposals and toStrings (Task 3) |
</threat_model>
