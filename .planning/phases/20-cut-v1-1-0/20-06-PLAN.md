Write scripts/verify-binary-diff.sh in the house style: usage `--old &lt;jar|aar&gt; --new &lt;jar|aar&gt; --api &lt;old api.txt&gt; [--out &lt;file&gt;]` and `--selftest`. Behavior: an .aar argument is reduced to its classes.jar (unzip -p); the set of classes to compare is exactly the classes declared in the OLD release's api.txt (public API only; Kotlin `internal` classes are public in bytecode and are not part of the contract), mapped to binary names (package path, nested `Outer.Inner` becomes `Outer$Inner`); a class named in the api.txt but absent from the old jar is an error naming it (api and jar disagree). A class that is wholly absent from the new jar fails too. Additions are counted, never failing. The last line is `BINARY DIFF OK classes=&lt;n&gt; removed=0 internal_removed=&lt;k&gt; added=&lt;m&gt;` or `BINARY DIFF FAIL: removed=&lt;n&gt;` (with each removed line printed before it, to the --out file when given); usage errors exit 2. `--selftest` compiles two tiny java source trees with javac and jar into a temp dir and requires: identical jars give OK; adding a method gives OK; removing a public constructor gives FAIL naming it; removing a class listed in the api file gives FAIL; removing a class NOT listed in the api file (internal) stays OK; an api file naming a class missing from the old jar is an error; it ends `BINARY DIFF SELFTEST OK cases=&lt;n&gt;` and removes its temp dir. No Gradle, no network. Run `bash -n`, the selftest, and append both final lines to tooling-proof.txt.</action>
