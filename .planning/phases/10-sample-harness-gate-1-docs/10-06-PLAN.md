## UI contract (inline; the harness is a dev tool, so no UI-SPEC.md, research open question 3)

- Root column, vertically scrollable, `Modifier.semantics { testTagsAsResourceId = true }`, keep-screen-on. Sections top to bottom: header, keys, legs, readout.
- Header: `okhttp_version` "okhttp <v>"; `fixture_state` banner: green "Fixture OK sha=ebd3ef4a…af4ed3e tools=<n> source=<files|asset>", red "FIXTURE ABSENT - push the LE-1 fixture (GATE1-RUNBOOK)", red "FIXTURE SHA MISMATCH <8hex> - do not use; ask the orchestrator to regenerate", red "FIXTURE MALFORMED <code>"; `budget_used` "requests <core>/33 · optional <o>/1 · est USD <x>"; `warm_window` "Anthropic warm window: wait <s> s" only while open (amber).
- Keys card, one row per provider p in anthropic, openai, openrouter: `key_state_<p>` (KeyUx label; Ready shows last 4), `key_field_<p>` (masked single-line), `key_save_<p>`, `key_delete_<p>`. Debug only: `import_test_keys` button and `import_status` text ("anthropic=Ready deleted=true in_datastore=false; ..." from ImportReport fields; never last 4).
- Legs list, one row per LegId in catalog order: button `run_<leg>` (disabled only while another leg is RUNNING) and text `status_<leg>` = `<STATUS>` or `<STATUS> reason=<code>`. Colors: PASS green; FAIL and REFUSED red; WARM, OUT_OF_BAND, INCONCLUSIVE, CAPTURED amber; RUNNING and IDLE neutral.
- Readout `readout`: the last leg's rendered outcome. A Failed outcome also shows `failure_banner` (red). A clarification shows `clarify_question` and one button `clarify_option_<id>` per option (label as text).
- Spacing 8 dp between controls, 16 dp between sections; Material 3 default typography; no images or icons.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user/tester input -> key field | a typed key enters the app |
| app -> screen | key state, outcomes and replies are displayed (and may be captured in screenshots or uiautomator dumps) |
| intent extras -> app | a debug intent can start a leg |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-24 | Information disclosure | a typed key or its last 4 reaching logs | high | mitigate | save path never logs; field cleared; canary test (Task 3); last 4 on screen only |
| T-10-25 | Information disclosure | live model text captured in screenshots or dumps that get committed | medium | mitigate | live replies shown as length only (Task 2); runbook forbids committing dumps/screenshots with model text |
| T-10-26 | Elevation of privilege | an external intent starting paid legs in a release build | medium | mitigate | autorun only in debug; release returns null (Task 3); budget still applies |
| T-10-27 | Repudiation | a failure that looks like success on screen | high | mitigate | tone rules, partial never "Done", red banners with codes (Tasks 1-2) |
| T-10-28 | Denial of service (cost) | double taps starting two legs | medium | mitigate | one leg at a time in the ViewModel and the runner mutex (Task 1) |
</threat_model>
