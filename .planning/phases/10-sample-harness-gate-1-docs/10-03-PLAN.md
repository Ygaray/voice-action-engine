Output: key slots and store factory, the KeyVault seam with cause-code UX, the plaintext scanner, debug and release DebugTools, three test classes.

Contention: wave 3 is this plan only; one Gradle invocation at a time.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host key store -> device app storage | push-test-key places a plaintext key file in app-private storage (D-13) |
| plaintext file -> :keystore | the importer must move the key into AES/GCM ciphertext and destroy the file |
| key state -> UI/logs | key state is shown and logged |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-10 | Information disclosure | plaintext key file left in app storage | high | mitigate | overwrite then delete, existence re-check, DataStore plaintext scan, report flags (Task 1); post-run verify-keys-gone and uninstall (10-07, runbook) |
| T-10-11 | Information disclosure | key or last 4 in logs, reports, exceptions or toString | high | mitigate | report carries state words and booleans only; canary test (Task 1); last 4 only in the on-screen label (Task 2) |
| T-10-12 | Elevation of privilege | release build able to import plaintext keys | medium | mitigate | importer only in src/debug; release no-op; dex check (Task 3) |
| T-10-13 | Tampering | alias collision with SB/CT stranding a key | medium | mitigate | sample-prefixed, distinct aliases and keys in the sample's own package and DataStore file (Task 2) |
| T-10-14 | Repudiation | a keystore failure shown as a generic error | low | mitigate | cause-code to action mapping with else branch (Task 2) |
</threat_model>
