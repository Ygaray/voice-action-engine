## Type contract (package `...core.commit`)

- `ConfirmationPolicy`: `public fun interface ConfirmationPolicy { public suspend fun subjectFor(proposal: CommitProposal): Any? }`. Returns null when no confirmation is needed (admit at once), else an app-typed subject the confirm UI renders.
- `ConfirmAmendHook`: `public fun interface ConfirmAmendHook { public suspend fun afterConfirm(proposal: CommitProposal, subject: Any?): List<PendingMutation>? }`. Runs after the user confirms and before Admit; returns an amended list (for example with a fresh pre-mutation snapshot and merge authorization in each mutation's context) or null to apply the proposal unchanged.
- `PendingConfirmation`: `public class PendingConfirmation internal constructor(id: Long, subject: Any?, proposal: CommitProposal)` with public vals `id`, `subject`, `proposal`; `toString` = `PendingConfirmation(id=<id>, subject=<simple class name|null>)` (SB `VoiceConfirmGate.kt:34` pattern).
- `AwaitingConfirmGate`: implements `PreApplyGate`. Public primary constructor `(policy: ConfirmationPolicy, timeoutMillis: Long, amendHook: ConfirmAmendHook?, heldOutcomeToken: String?)` with `require(timeoutMillis > 0)`, plus secondaries `(policy)` and `(policy, timeoutMillis)` (defaults: 120_000 ms as a top-level private const, no hook, no token). Public `pending: StateFlow<PendingConfirmation?>`; `public fun resolve(confirmationId: Long, confirmed: Boolean): Boolean` (true only when it completed the active confirmation). `admit`: ask the policy; null subject gives `GateDecision.Admit()`; otherwise, holding a `Mutex` for the whole window, publish a new `PendingConfirmation` (monotonic id from an `AtomicLong`), await a `CompletableDeferred<Boolean>` inside `withTimeoutOrNull(timeoutMillis)`, and in `finally` clear both the active slot and `pending`. `true` gives `Admit(amended)` when the hook returns a list, else `Admit()`; anything else (false, timeout) gives `GateDecision.Hold(subject, heldOutcomeToken)` (the reason is the app's own subject; the engine constructs none). Policy and hook exceptions propagate (the engine's gate step turns them into a fail-closed Hold with trace code gate_error). A `CancellationException` while pending propagates and is never converted into a decision. `toString` = `AwaitingConfirmGate(timeoutMillis=<n>, pending=<id|none>)`.
- KDoc (hand-off notes, no planning ids): dispatch is sequential because the mutex is held for the whole confirmation window; the engine adds no timeout around admit beyond this gate's own window; an app that sets `TierPolicy.commandTimeoutMillis` shorter than the window will have its deadline end the wait as `Failed(Timeout)` with nothing recorded.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app UI -> gate | the user's confirm/decline arrives through resolve(id, confirmed) |
| app policy/hook -> gate | app code decides what needs confirmation and may amend the write |
| model -> terminal call | clarification arguments are model-generated |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-30 | Elevation of privilege | confirm bypass on timeout, decline or error | high | mitigate | Only `confirmed == true` admits; timeout/decline give Hold; policy/hook errors propagate to the engine's fail-closed gate step; tests for each |
| T-02-31 | Spoofing | a stale or replayed resolve admitting a different write | high | mitigate | Monotonic ids, id-checked CompletableDeferred completion, second resolve returns false; tests |
| T-02-32 | Tampering | interleaved concurrent confirmations applying the wrong write | medium | mitigate | Mutex held for the whole window; serialization test |
| T-02-33 | Information disclosure | confirm subject (note titles, food names) in toString or logs | medium | mitigate | PendingConfirmation/AwaitingConfirmGate toString print id and class name only; canary test |
| T-02-34 | Denial of service | an unanswered confirmation blocking forever | low | mitigate | 120 s default window, configurable, fail-closed Hold |
</threat_model>
