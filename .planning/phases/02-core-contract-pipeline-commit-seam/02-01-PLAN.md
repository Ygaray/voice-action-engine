## Type contract (exact public shapes this plan creates)

All types are regular final classes unless stated; every public member has KDoc; no Kotlin copy/componentN-generating class modifier anywhere; constants are top-level `private const val` (never a `private companion object` constant, which leaks a public static field into api.txt).

- `CommandInput` (package `...core`): public constructor `(transcript: String, language: String? = null, context: Any? = null, parentRunId: String? = null)`. Properties with the same names. KDoc: language is `"en"`, `"es"` or null; context is an opaque app object the engine never inspects (D-04); parentRunId links a follow-up command to the run it answers (D-22). `toString` = `CommandInput(transcriptLength=<n>, language=<value|null>, context=<simple class name|null>, parentRunId=<id|null>)`. No validation (constructing input never throws). Deviation recorded: research suggested `context: Map<String, Any?>`; D-04 (locked) says opaque `Any?`, so `Any?` wins.
- `ProviderId` (package `...core`): `@JvmInline public value class ProviderId(public val value: String)`, `init` requires non-blank. `public companion object` with `ANTHROPIC = ProviderId("anthropic")`, `OPENAI = ProviderId("openai")`, `OPENROUTER = ProviderId("openrouter")`, `ON_DEVICE = ProviderId("on_device")`. `toString()` returns `value`.
- `StrategyId` (package `...core`): `@JvmInline public value class StrategyId(public val value: String)`, `init` requires non-blank, `toString()` returns `value`. KDoc: stable id the app may persist (for example as `TierPolicy.maxTier`); never a ladder index.
- `Credential` (package `...core`): public constructor `(provider: ProviderId, apiKey: String)`, `init` requires `apiKey` non-blank. `toString` = `Credential(provider=<value>)` (never the key, never its length). No equals override. KDoc: Phase 3 adds a typed credential source around it.
- `FailureReason` (package `...core.failure`): `public interface FailureReason { public val code: String }`, NOT sealed. Nested public leaf classes, each with a public constructor, equals/hashCode by concrete class and constructor fields, and `toString` = `FailureReason.<Leaf>(code=<code>[, <field>=<value>])`. Leaves and codes: `Auth` auth, `Billing` billing, `RateLimited` rate_limited, `Overloaded` overloaded, `Timeout` timeout, `Network` network, `MalformedResponse` malformed_response, `MalformedToolArgs` malformed_tool_args, `Refusal` refusal, `MaxTokens` max_tokens, `NoToolCall` no_tool_call, `BudgetExceeded(bound: BudgetBound)` budget_exceeded, `ToolFailure` tool_failure, `NotConfigured(provider: ProviderId?)` not_configured, `ProviderUnavailable(provider: ProviderId, cause: String?)` provider_unavailable, `ModelUnsupported` model_unsupported, `ModelNotFound` model_not_found, `PauseTurn` pause_turn, `ContextWindowExceeded` context_window_exceeded, `UnknownStop` unknown_stop, `HttpError` http_error, `NoEligibleTier` no_eligible_tier, `PolicyUnavailable` policy_unavailable, `Unexpected(errorClass: String)` unexpected, `Other(code: String)` (code = the given code; `init` requires non-blank). KDoc on the interface: the set is open, consumers must keep an `else` branch; `cause` and `Other.code` are stable codes, never messages.
- `FailureDetails` (package `...core.failure`): public constructor `(httpStatus: Int?, providerErrorType: String?, requestId: String?)`, equals/hashCode by the three, `toString` prints the three. KDoc: never a response body.
- `EscalationReason` (package `...core.failure`): `public interface EscalationReason { public val code: String }`, NOT sealed. Nested leaves, same conventions: `NoToolCall` no_tool_call, `ModelDeclined` model_declined, `MalformedExtraction` malformed_extraction, `ResolverAmbiguous` resolver_ambiguous, `ProviderUnavailable(provider: ProviderId)` provider_unavailable, `Other(code: String)`.
- `BudgetBound` (package `...core.failure`): `@JvmInline public value class BudgetBound internal constructor(public val value: String)`, companion `ITERATIONS` ("iterations"), `TOKENS` ("tokens"), `toString()` = value. KDoc: open set, keep an `else`.
- `TierPolicy` (package `...core.pipeline`): `internal` primary constructor; public read-only properties `offlineOnly: Boolean`, `maxTier: StrategyId?`, `allowedProviders: Set<ProviderId>?` (null = every provider), `maxIterations: Int`, `tokenCeiling: Long`, `maxTokensPerTurn: Int`, `commandTimeoutMillis: Long?` (null = no engine deadline). Nested `public class Builder internal constructor()` with public `var`s of the same names and defaults false / null / null / 6 / 60_000 / 4_096 / null. `public companion object` with `DEFAULT: TierPolicy` and `public operator fun invoke(block: Builder.() -> Unit): TierPolicy` (so callers write `TierPolicy { maxIterations = 8 }`). Build validation with `require`: maxIterations >= 2, tokenCeiling > 0, maxTokensPerTurn > 0, commandTimeoutMillis null or > 0. `toString` prints every field. Defaults as top-level private consts (`DEFAULT_MAX_ITERATIONS`, `DEFAULT_TOKEN_CEILING`, `DEFAULT_MAX_TOKENS_PER_TURN`, `MIN_ITERATIONS`) because detekt MagicNumber is active in main.
- `TierPolicySource` (package `...core.pipeline`): `public fun interface TierPolicySource { public suspend fun current(): TierPolicy }` with `public companion object { public fun fixed(policy: TierPolicy): TierPolicySource }`.

## Assumptions / Open for orchestrator (planner-resolved; none blocks execution)

1. O1 ToolSpec ownership: Phase 2 ships a minimal `ToolSpec` (name, description, inputSchema, mutating, terminal; terminal+mutating rejected at construction) plus `ToolSpec.clarification(...)` (plan 02). Phase 3 adds strict/cache members additively; Phase 3's `terminal` field decision is satisfied here.
2. O2 cancellation around a write (plan 05): `onAction` is delivered under `NonCancellable`; a cancel during `apply()` records an `is_error`, `applied = true` action (it may have partially written), delivers it, then rethrows; a cancel while the gate is suspended records nothing.
3. O3 CORE-05 reading (plans 02, 04): real cancellation always propagates; a `TimeoutCancellationException` that leaks from app code while the run is still active becomes `Failed(Timeout)`; a plain `CancellationException` thrown by app code propagates.
4. O4: `CommandOutcome` leaf constructors stay internal; consumers build outcomes in their tests by running a pipeline with a small custom strategy.
5. O5: the gate amends through `Admit(amended)`; the `ActionEvent` exposes the amended mutation's `context` (SB's snapshot + merge authorization ride there).
6. A2: a tier that only held and then escalates ends `Completed(partial = true)` with the held proposals listed (D-15/D-16).
7. A3: a sink that throws after a successful apply is caught and recorded as trace code `sink_error`; the apply is never repeated and the action stays in the executed list.
8. A4: a second `commitHeld` returns the first call's outcome with no apply and no events; if the first call was cancelled, later calls return `Failed(Other("commit_held_cancelled"))` carrying the child run's executed-so-far (never throw).
9. A5: `maxIterations < 2` fails `TierPolicy` construction with `IllegalArgumentException`; a throwing `TierPolicySource` becomes `Failed(PolicyUnavailable)` with zero strategy executions.
10. A6: `GateDecision.Hold` carries an optional `appOutcomeToken` so SB keeps its verbatim `"held"` token; engine fail-closed holds carry null.
11. A7: `TerminalCall.asClarification()` returns null (never throws) for non-conforming arguments; empty options are allowed.
12. A8: `clock` and `runIds` are public optional DSL properties (Kotlin function types) so other modules' tests can make traces deterministic.
13. A9: no engine cap on `CommitSink` delay.
14. `Credential` ships here because ROADMAP Phase 6 depends on Phase 2 for `ProviderId` + `Credential`.
15. `TierSelector.Fixed(id)` naming a tier that is not in the ladder is build-time misconfiguration and throws at `commandPipeline {}` (D-17); a tier excluded at run time by `maxTier` yields `Failed(NoEligibleTier)` (research's test map had both at run time).
16. SC2 "enforces 6 / 60,000 / 4,096": the pipeline enforces `maxTier`, `allowedProviders` and `offlineOnly` itself; iteration, token-ceiling and per-turn limits are exposed on `session.policy` plus a run-cumulative `session.tokensUsed` (plan 08), and the strategies that loop (Phases 7 and 9) enforce and prove them.
17. `TierPolicy.commandTimeoutMillis` defaults to null (no engine deadline), so SB's 120 s confirm window is never cut by the engine (D-23); an app that sets it accepts that its deadline also bounds a suspended gate.
18. `maxTier` naming a `StrategyId` absent from the ladder yields a loud `Failed(NoEligibleTier)` plus trace code `max_tier_unknown`, never a silent "no cap".
19. A tier whose declared providers are exactly `{ON_DEVICE}`, reached while on-device is unavailable, ends the run `Failed(ProviderUnavailable(ON_DEVICE, "on_device_unavailable"))` without running and never climbs to a cloud tier (CORE-04 orchestrator ruling at pipeline level; Phase 3 adds declared fallbacks).
20. `ProviderId` wire strings are lowercase (research A1).
21. Plan shape: 9 plans / 6 waves instead of research's 6 / 5, so every plan leads with a real tracer, same-wave plans own disjoint files, and the commit plan is split (coordinator vs run-level safety) to fit a context budget.
