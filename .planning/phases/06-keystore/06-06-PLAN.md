<objective>
Give the store its real key custody and its public constructors, then author the one instrumented class that proves the real AndroidKeyStore path on the TESTER (KEY-02, KEY-03, KEY-04; D-06 device leg, D-10, D-11). `AndroidKeyStoreKeyAccess` uses `getKey` so a transient Keystore2 error can never be mistaken for an absent key (the latent defect in both ports), and creates keys only under one process-wide lock with the ports' exact spec. Everything here is built, linted and JVM-tested offline; the device run is 06-07's final task.

Purpose: SC3's "synchronized get-or-create" and "never creates a key on decrypt" must hold on real hardware, and SC2/SC4 need a real-Keystore compat and round-trip test; this plan makes them runnable.
Output: one platform class, two public constructors, one JVM test, two androidTest files.

Contention: the phase runs strictly sequentially, one plan per wave (wave 6 is this plan only; it starts after 06-05 has merged), so no two plans ever run `:keystore` Gradle tasks at the same time; this plan never runs two Gradle invocations at once and uses task-scoped `:keystore` commands until its final `:keystore:check :core:check`.
</objective>
